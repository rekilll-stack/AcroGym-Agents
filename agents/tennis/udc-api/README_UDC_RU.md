# API для бронирования корта в UDC

Готовый клиент API для бронирования корта в UDC: приоритет двух последовательных часов на одном корте, один час как запасной вариант, проверка существующих броней и ссылки для самостоятельной оплаты. Python 3.10+, стандартная библиотека; нужен доступ к HTTPS и база часовых поясов с `Asia/Qatar`.

## API для бронирования корта в UDC — исправление сетевых сбоев 16 октября 2026

Лимит ожидания ответа увеличен с 25 до 60 секунд. Вход, каталог, слоты и история могут повторяться при транспортной ошибке, HTTP 408 или HTTP 5xx: максимум три попытки всего, паузы 2 и 4 секунды. Ошибочный логин, HTTP 400/401/403/429 и неверная структура ответа не повторяются. Ошибка чтения указывает маршрут, этап, тип исключения и число попыток без содержимого запросов и секретов.

Создание брони и `Payment/paymentAuth` выполняются по одной попытке. После таймаута, обрыва ответа или HTTP 5xx запрос записи не повторяется; сначала проверяется история. Правила повторов передачи подтверждений на сервер владельца остаются отдельными: первоначальный запрос и максимум три повтора через 60 секунд.

## API для бронирования корта в UDC — отдельно разрешённая разовая бронь

Только по явной просьбе владельца о разовой или тестовой брони можно выполнить:

```bash
python3 udc_booker.py --execute-once 2026-10-19 --window morning --username kirill
```

Это реальная бронь выбранного окна. Дата должна находиться в пределах сегодня–+7 дней по Дохе. Действуют прежние корты, будни, окна и приоритет двух соседних часов; при отсутствии пары допустим один час. Пятница и суббота как даты игры запрещены. Утро допустимо только в понедельник. Уже начавшееся окно отклоняется. Перед каждой записью перечитывается история, после записи проверяются идентификатор, время, корт и цена. Время создания разовой брони может отличаться от полуночи; автоматический `--execute-scheduled` по-прежнему работает только в 00:00–00:05 и на дату +7. Разовую команду не добавлять в расписание. Оплата остаётся ручной.

## API для бронирования корта в UDC — правила

Воскресенье–четверг: попытка в 00:00 `Asia/Qatar`, целевая дата — местная дата запуска +7 календарных дней. Вечернее окно — 18:00–21:00. По понедельникам дополнительно отдельное утреннее окно 07:00–09:00. Пятница и суббота исключены.

Сначала ищется пара часовых слотов подряд на одном корте: 18–20 или 19–21; утром 7–9. При отсутствии пары на обоих кортах разрешён один час внутри окна. Любой из Giardino/GV и Family Park/Costa Malaz подходит. Если уже есть один час, добавляется только соседний час на том же корте; новая пара поверх него не создаётся. Максимум два часа на окно; в понедельник утро и вечер независимы. При неудаче второго запроса первый час сохраняется.

Цена берётся из актуального ответа UDC. Фиксированного тарифа в программе нет. В Family Park фильтруется именно теннис: этот объект также возвращает слоты другого вида спорта. Статусы и ещё не истёкшие резервы учитываются перед каждым созданием. При неоднозначном результате запроса программа проверяет историю и прекращает дальнейшие записи; автоматического повторения такого запроса нет.

## API для бронирования корта в UDC — запуск и тесты

Распаковать архив и выполнять команды из его папки. Пароль вводится скрыто через `getpass`; в архив его не включать. Для автоматизированного окружения поддерживается переменная `UDC_PASSWORD`, которую следует предоставлять через настройки секретов исполнителя. Логин: `kirill`.

```bash
python3 -m unittest -v test_udc_booker.py test_udc_report.py
python3 udc_booker.py --check-login --username kirill
python3 udc_booker.py --preview 2026-10-25 --username kirill
python3 udc_booker.py --status 2026-10-25 --username kirill
```

`--preview` и `--status` не создают броней или платёжных сессий. Предпросмотр без `--username` доступен для публичных слотов, но не учитывает историю аккаунта. Для проверки перед фактическим бронированием использовать авторизованный режим.

Единичный запуск по расписанию:

```bash
python3 udc_booker.py --execute-scheduled --username kirill
```

Команда сама вычисляет дату +7 и разрешает создание только в промежутке 00:00–00:05 Дохи в нужные дни. Время проверяется перед каждым запросом создания. Поздний запуск не даёт разрешения обойти ограничение. Запросы могут занять секунды после запуска: время прихода HTTP-запроса на сервер ровно в 00:00:00 не гарантируется.

Постоянный исполнитель для отдельного Linux/macOS-хоста:

```bash
python3 udc_scheduler.py --username kirill
```

Пароль запрашивается один раз и остаётся в памяти процесса. Процесс и доступ к сети должны работать постоянно. Перед каждой попыткой планировщик сохраняет местную дату; перезапуск не повторяет этот день. После аварийного завершения это может привести к пропуску, поэтому результат проверяется командой `--status`. Состояние по умолчанию находится в `~/.local/state/udc-court-booking`; путь меняется через `--state-dir`. Пароля и токенов там нет. Не удалять состояние ради повторного создания после неопределённого результата.

На одном аккаунте должен работать один исполнитель. При переносе задачи сначала отключить прежний исполнитель. Локальная блокировка не защищает от второго процесса на другом хосте. Расписание уже существующей задачи следует обновлять, а не создавать дубликат.

## API для бронирования корта в UDC — оплата

Два часа оформляются как две соседние часовые брони, поскольку API для обоих кортов вернул длительность 60 минут. Для каждого своего ожидающего оплаты резерва программа запрашивает `Payment/paymentAuth` и выводит полученную HTTPS-ссылку, сумму, номер и срок. Владелец самостоятельно открывает ссылку и оплачивает. Суммы разных броней под одним идентификатором не объединяются.

Если резерв уже оплачен, новая ссылка не создаётся. При нулевой сумме платёжная сессия не создаётся. Неизвестный статус, цена, повреждённый ответ или ссылка выводятся как требующие проверки. Получение ссылки само по себе не подтверждает оплату. Окончательное подтверждение — `status = Active` и `paymentStatus = Confirmed` у каждого часа в истории.

При необходимости снова получить ссылки для своих существующих резервов:

```bash
python3 udc_booker.py --payment-links 2026-10-25 --username kirill
```

Эта команда создаёт платёжные сессии, но не создаёт новые брони и не выполняет платёж. После неопределённого ответа создания сессии не запускать её повторно вслепую. Сроки брать из фактического ответа UDC; фиксированное время действия ссылки не обещается.

## API для бронирования корта в UDC — методы и формат

База: `https://tpiapp.udcqatar.com/api/`. Исходная опубликованная схема: `https://tpiapp.udcqatar.com/swagger/v1/swagger.json` (получена 15 октября 2026). Используется JSON; после входа — `Authorization: Bearer <token>`.

| Метод | Назначение API для бронирования корта в UDC |
| --- | --- |
| `POST Account/login` | Получить токен: `userName`, `password`, `rememberMe: false`, `userTimeZoneOffset: 180` |
| `GET Amenities/GetAll` | Прочитать каталог и параметры двух кортов |
| `POST Amenities/GetDuration` | Прочитать допустимую длительность слотов; при исследовании оба корта вернули `[60]` |
| `POST Amenities/GetAllSlots` | Слоты корта на дату: `amenityId`, `bookingDate`, `pageSize: 100`, `pageNumber: 1` |
| `GET Amenities/GetBookedAmenity` | Прочитать собственные брони и статусы оплаты |
| `POST Amenities/BookAmenities` | Создать одну часовую бронь |
| `POST Payment/paymentAuth` | Создать платёжную сессию и получить `redirectURL` для одной своей брони |

Формат ответа: `result.successful`, `result.codeStatus`, `result.message`, `result.data` внутри внешнего JSON-объекта. HTTP 200 с `successful: false` считается ошибкой. Полные поля, типы и дополнительные связанные методы приведены в OpenAPI. Клиент использует только разрешённые маршруты и не выполняет автоматическое списание.

Для `GetAllSlots` и `BookAmenities` поле `bookingDate` передаётся как `YYYY-MM-DDT00:00:00` без часового суффикса: добавление `+03:00` при реальной проверке сдвигало возвращаемый день. Начало/конец часовой брони передаются с `+03:00`. Клиент проверяет день недели и идентификатор корта в ответе слотов.

Теннисный тип проверяется по Giardino/GV: на момент проверки `100000001`. Идентификатор GV: `b69ef8b8-fe79-ec11-8d22-0022489cbcfa`. Идентификатор Family Park/Costa Malaz: `b89ef8b8-fe79-ec11-8d22-0022489cbcfa`. `bookingDayId`, `bookingTimeSlotId`, стоимость, необходимость оплаты и `precinctLock` берутся из текущего ответа сервера.

Для `BookAmenities` формируются `amenityId`, `amenityTypeId`, `isPaymentRequired`, `bookingDate`, `bookingDayId`, `bookingStartTime`, `bookingEndTime`, `bookingTimeSlotId`, `bookingCharges`, `bookingChargesAfterDiscount`, `precinctLock`. Оба ценовых поля равны фактической стоимости слота; скидки не выдумываются. Необязательный `languageId` не подставляется без подтверждённого значения.

Для `paymentAuth` передаются `bookedAmenityId` и `order: {amount: "100.00", currency: "QAR", description: "UDC tennis court booking"}`. Здесь `100.00` — пример формата; программа подставляет точную стоимость соответствующей брони из истории.

## API для бронирования корта в UDC — пределы проверки

Автоматические тесты прошли. На реальном API проверены вход, чтение истории, каталога, слотов и допустимой длительности. 15 октября 2026 авторизованный предпросмотр на 19 октября показал: вечером мест нет, утром доступен один час Giardino 08:00–09:00 с серверной ценой 0 QAR.

16 октября 2026 по прямой просьбе владельца выполнено реальное создание одного бесплатного часа: AB-49363, Giardino 19 октября 08:00–09:00. Собственная история подтвердила Active / Confirmed и 0 QAR; сервер принял передачу с calendar=true. Реальная пара на два часа, создание платёжной сессии и оплата платного резерва отдельно ещё не проверены. Клиент останавливается при непроверяемом результате и сохраняет полученные номера броней.

В реальной записи UDC обнаружено расхождение: bookingTimeSlot показывает 08:00–09:00 по Дохе, а обе служебные UTC-метки после обычного преобразования показывают 05:00–06:00. Клиент использует локальные bookingDate + bookingTimeSlot, если метки совпадают с ними либо обе отличаются ровно на этот подтверждённый трёхчасовой сдвиг. Иное расхождение требует проверки; при отсутствии отображаемого слота сохраняется обычное преобразование UTC в Доху. Это также защищает от повторного создания уже существующей брони.

Срок оплаты 12 часов не подтверждён. В прочитанной истории у всех 54 платных резервов поле bookingExpiry было через 300 секунд после createdDate. Это наблюдение о сроке резерва, а не проверка длительности новой платёжной сессии. При создании платного резерва ссылку и фактический срок UDC нужно сразу сообщить владельцу; произвольное продление не реализовано.

## API для бронирования корта в UDC — актуальный адрес подтверждений

Подтверждённые игры передаются на `https://hook.acrogym.org/tennis`. Доступ с предоставленным ключом проверен запросом `{"date":"bad"}`: сервер вернул ожидаемую ошибку формата 400, без создания события. Клиент и схема Actions используют новый адрес. При сетевой ошибке или HTTP 5xx допускаются три повтора с паузой 60 секунд, то есть максимум четыре запроса вместе с первоначальным. Для последующего обнаружения оплаты предусмотрены отдельное задание раз в час либо процесс `udc_confirmation_worker.py` на собственном постоянно включённом хосте.

## API для бронирования корта в UDC — выдача ссылок на оплату

Ссылки для ручной оплаты сообщаются владельцу в этом чате в результате полуночного задания бронирования: дата, часы, сумма каждого резерва, ссылка и срок из ответа UDC. Для каждого платного часового резерва своя ссылка. В тело передачи подтверждений на сервер владельца платёжные ссылки не включаются: там только дата, часы и корт. 15 октября 2026 владелец подтвердил внешнюю проверку доступа и записи на сервер и разрешил передачу настоящих подтверждённых броней.
