## API для бронирования корта в UDC — автоматические проверки

Команда: `python3 -m unittest -q test_udc_booker.py test_udc_report.py`.
Результат: 98 тестов, успешно. В тестах используются синтетические записи, идентификаторы и секреты; реальные брони и платежи они не создают.

Проверены выбор двух соседних часов на одном корте и одиночный запасной час, существующие резервы, отдельные утро и вечер понедельника, разрешённые дни и окна Дохи, проверка истории после записи, остановка при неопределённом результате, цена и правила получения платёжных ссылок. Отдельно проверены ограничения разовой брони и сохранение полуночного ограничения запуска по расписанию.

Проверки передачи подтверждений охватывают Active / Confirmed, ожидание оплаты обоих соседних резервов, объединение только соседних часов одного корта, четыре разрешённых поля, Bearer, запрет перенаправления ключа, calendar=true/false, duplicate, ошибки 400/401/403, журнал и запрет повторной перекрывающейся записи. При сетевой ошибке или 5xx проверены максимум четыре запроса одного тела и паузы 60 секунд через подставной таймер.

Новые проверки транспорта охватывают задержку дольше прежнего лимита, повтор безопасного чтения, предел попыток и пауз, обрыв тела ответа, закрытие ответа и диагностику без секретов. Создание брони и платёжной сессии после неопределённого результата не повторяется. Проверки истории охватывают фактически наблюдавшееся расхождение времени, отказ при другом или неодинаковом сдвиге, защиту от повторной брони и передачу правильного локального времени.

Методы записи брони и платёжной сессии выполняются однократно. Диагностика содержит маршрут, этап, класс причины, число попыток и лимит без токенов и тела запроса.

## API для бронирования корта в UDC — время в истории

У этой брони bookingTimeSlot равен 08:00–09:00, bookingDate содержит 2026-10-19. Служебные метки начала 2026-10-19T02:00:00Z и конца 2026-10-19T03:00:00Z после обычного перевода в Доху дают время на три часа раньше локального слота. Из-за этого прежняя обработка ошибочно не находила созданный утренний час. Бронь повторно не создавалась.

Исправленный клиент использует дату и локальный слот после проверки обеих служебных меток: допустимы совпадение либо наблюдавшийся одинаковый сдвиг на три часа. Другое расхождение требует проверки и останавливает обработку. При отсутствии локального слота сохраняется обычный перевод UTC в Доху. Исправление применяется к поиску собственных резервов и передаче подтверждений.

Локальный журнал принятой записи сохранён; повторная отправка для испытания не выполнялась. Изменения календаря и Джарвиса напрямую клиентом не выполнялись. Отдельная проверка уведомления и подавления заявки другим агентом не проводилась.

Ранее безопасная проверка с неверной датой вернула ожидаемый HTTP 400 без создания события. Рабочий маршрут — hook.acrogym.org; прежний адрес не используется.

## API для бронирования корта в UDC — сроки оплаты

Прочитана история 54 платных резервов. У каждого bookingExpiry был через 300 секунд после createdDate. Это наблюдение о сроке резерва, а не проверка срока жизни платёжной ссылки или текущего нового платёжного сеанса. Обещать 12 часов на оплату нельзя. При получении ссылки её нужно сразу передавать владельцу в чат вместе с датой, временем, кортом, суммой и фактическим сроком из ответа UDC. Два платных часовых резерва могут требовать отдельных ссылок.
