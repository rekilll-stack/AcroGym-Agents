# API для бронирования корта в UDC — начать здесь

Используй готовую реализацию API для бронирования корта в UDC из этого архива. Внутри находятся полный исходный код, схема запросов и ответов, правила, планировщик, тесты и отчёт проверки. Основные функции уже написаны; ниже — порядок переноса и запуска.

## API для бронирования корта в UDC — порядок работы

1. Прочитай `README_UDC_RU.md`, `UDC_Court_Booking_Requirements.md` и `TEST_REPORT_UDC_RU.md`.
2. Используй Python 3.10+ с доступом к HTTPS и часовому поясу `Asia/Qatar`. Программы используют стандартную библиотеку. В минимальном окружении установи системную базу часовых поясов, если она отсутствует.
3. Запусти `python3 -m unittest -v test_udc_booker.py test_udc_report.py`. В приложенной версии прошли 98 тестов. Они не отправляют запросы создания в реальный API для бронирования корта в UDC.
4. Используй логин `kirill`. Пароль владелец предоставляет отдельно через скрытый ввод или секрет `UDC_PASSWORD`. Пароля и действующих токенов в архиве нет; в исходники, аргументы командной строки и отчёты их не записывать.
5. Проверь вход, историю и план доступных слотов командами ниже. Эти команды не создают резервов и платёжных сессий.
6. Подготовь один исполнитель расписания API для бронирования корта в UDC. При переносе сначала отключи прежний исполнитель. Две одновременно работающие копии на разных хостах недопустимы; локальная блокировка не является распределённой.
7. Автоматическое создание выполняй в предусмотренное время и проверяй фактические ответы сервера. Отдельная разовая или тестовая бронь требует явной просьбы владельца; используй `--execute-once YYYY-MM-DD --window evening|morning`, не меняя расписание. Сохрани защитные проверки программы; об ошибке сообщи владельцу с полученными номерами резервов, если они есть.

```bash
python3 udc_booker.py --check-login --username kirill
python3 udc_booker.py --preview 2026-10-25 --username kirill
python3 udc_booker.py --status 2026-10-25 --username kirill
```

Дата 2026-10-25 — пример для первого предусмотренного запуска 18 октября 2026. Для последующих проверок подставляется соответствующая целевая дата. Исполнитель `--execute-scheduled` вычисляет дату самостоятельно.

## API для бронирования корта в UDC — обязательные правила

- Запуск: 00:00 `Asia/Qatar`, воскресенье–четверг. Целевая дата — местная дата запуска +7 календарных дней. Пятница и суббота исключены.
- Вечером выбирай два соседних часа на одном корте внутри 18:00–21:00: 18–20 либо 19–21. Только при отсутствии пары на обоих допустимых кортах разрешён один час внутри окна.
- В понедельник дополнительно отдельное утреннее окно 07:00–09:00: приоритет 07–09, запасной вариант — один час. Утро и вечер независимы.
- Только теннис и только Giardino/GV либо Family Park/Costa Malaz. Family Park возвращает также слоты другого вида спорта, которые программа исключает.
- Перед созданием проверяй свою историю, включая неистёкшие неоплаченные резервы. Один уже имеющийся час дополняй только соседним часом того же корта. При двух существующих часах больше не создавай. Максимум два часовых резерва на окно.
- Если второй час создать не удалось, сохраняй первый. Самостоятельной отмены нет.
- Используй актуальные стоимость и параметры сервера. Не подставляй произвольные скидки и не обходи лимиты.
- После неопределённого ответа создания перечитай историю и останови дальнейшие записи. Не повторяй запрос вслепую. Явный конфликт доступности допускает обновление слотов; максимум три запроса создания на окно.
- Требования документов, QID, договора аренды, неизвестный статус, изменение цены или непроверяемый результат передавай владельцу.

## API для бронирования корта в UDC — расписание

Для постоянно работающего отдельного Linux/macOS-хоста:

```bash
python3 udc_scheduler.py --username kirill
```

Этот процесс должен оставаться включённым и иметь доступ к сети. Пароль запрашивается один раз и остаётся в памяти. Планировщик хранит дату попытки без секретов и не повторяет тот же день после перезапуска. Аварийное завершение может привести к пропуску попытки; состояние не удалять ради слепого повторного создания. Сначала проверяется `--status`.

Если используется уже существующий внешний планировщик, он должен запускать только эту команду в 00:00 Дохи по воскресеньям–четвергам:

```bash
python3 udc_booker.py --execute-scheduled --username kirill
```

Выбери один способ запуска. `schedule.ics` содержит расписание для переноса, но само по себе не исполняет программу. Клиент прекращает создание после 00:05 и повторно проверяет время перед каждой записью. Подготовка среды, вход и сеть могут задержать запрос относительно 00:00:00; точное время прихода запроса на сервер не гарантируется.

## API для бронирования корта в UDC — оплата

Программа создаёт резерв через `Amenities/BookAmenities`, проверяет его в собственной истории и запрашивает `Payment/paymentAuth` для получения официальной HTTPS-ссылки. Владелец открывает ссылку и оплачивает самостоятельно. Данные карты и автоматическое списание в программе не используются.

Два часа оформляются как две часовые брони с отдельными идентификаторами. Для каждой платёжной сессии берётся фактическая сумма именно этого часа в QAR. Если нужны две оплаты, возвращаются две отдельные ссылки; общую сумму нельзя приписывать одному идентификатору.

Для уже оплаченных и нулевых резервов новая платёжная сессия не создаётся. Если статус или сумма не позволяют безопасно создать ссылку, выводится необходимость проверки. Срок оплаты и срок истечения брать из реального ответа UDC. Полученная ссылка не означает, что бронь оплачена.

```bash
python3 udc_booker.py --payment-links 2026-10-25 --username kirill
python3 udc_booker.py --status 2026-10-25 --username kirill
```

`--payment-links` создаёт платёжные сессии только для своих существующих резервов; это запрос записи, хотя он не списывает деньги и не создаёт новых броней. После неопределённого ответа не повторять его вслепую. `--status` только читает историю. Подтверждение каждого часа: `status = Active` и `paymentStatus = Confirmed`. Непроверенную запись и ожидание оплаты подтверждением не называть.

## API для бронирования корта в UDC — что проверено

98 автоматических тестов прошли, в том числе выбор пары, частичный результат, понедельник, защита от дублей, ошибки API, отдельные платёжные запросы, проверка ссылок, планировщик, безопасные повторы чтения, ограничения разового режима и исправление времени истории UDC. На реальном API проверены вход, каталог, история, слоты и допустимая длительность 60 минут для обоих кортов.

16 октября 2026 по прямой просьбе владельца создана и проверена реальная бронь AB-49363: Giardino, 19 октября 08:00–09:00, 0 QAR, Active / Confirmed. Сервер принял подтверждение с calendar=true. Создание платёжной сессии, фактическая оплата и реальная пара на два часа пока отдельно не проверены; для бесплатной брони платёж не потребовался.

История UDC может содержать обе служебные метки времени на три часа раньше локального слота. Для точного подтверждённого расхождения используется bookingDate + bookingTimeSlot; произвольное расхождение останавливает обработку. У всех 54 прошлых платных резервов в прочитанной истории bookingExpiry было через 300 секунд после createdDate. Это срок резерва, а не проверенный срок платёжной ссылки. Оплату через 12 часов не обещать.

## API для бронирования корта в UDC — отчёт владельцу

По каждому нужному окну сообщай дату, корт, часы, фактическую длительность, цену каждого часа и итог, номера и статусы резервов, платёжные ссылки и сроки. Если двух часов нет, явно укажи запасной один час. При отсутствии мест, ошибке или непроверяемом результате сообщи причину без секретов.

Подробные поля и форматы API для бронирования корта в UDC находятся в `udc-court-booking.openapi.json`. Полный текст всех материалов в одном файле — `UDC_Court_Booking_API.txt`.

## API для бронирования корта в UDC — передача подтверждений

Добавлена передача подтверждённых игр в серверный API владельца. Прочитай `CONFIRMED_UDC_INTEGRATION_RU.md` и `SERVER_SETUP_UDC_RU.md`. Модуль отправляет только четыре разрешённых поля, объединяет соседние часы и прекращает запросы при ошибке доступа. Ключ предоставляется отдельно скрытым вводом или настройками секретов. Новый адрес передачи — `https://hook.acrogym.org/tennis`. Безопасный POST с неверной датой и ключом вернул ожидаемую ошибку 400; ключ принят, запись не создана. 15 октября 2026 владелец передал подтверждение внешней проверки: доступ и запись работают, можно отправлять настоящие подтверждённые брони. Это подтверждение владельца; для каждой игры результат всё равно определяется ответом сервера. Для сетевой ошибки и HTTP 5xx реализованы до трёх повторов с паузой 60 секунд; остальные защитные проверки сохраняются.
