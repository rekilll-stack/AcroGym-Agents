# API для бронирования корта в UDC — доступ к передаче подтверждений

Актуальный адрес: `POST https://hook.acrogym.org/tennis`. Использовать именно этот адрес. Проверка выполнена 15 октября 2026 с предоставленным владельцем ключом в Bearer и телом `{"date":"bad"}`.

Фактический ответ: HTTP 400, `{"ok":false,"err":"need date YYYY-MM-DD, from and to HH:MM (to after from), court optional"}`. По предоставленному серверному контракту это подтверждает принятие ключа и доступность приложения. Игра при такой проверке не создаётся. Ключ вводился скрыто и в архив не включён.

Предыдущая блокировка Cloudflare относилась к старому адресу. На новый маршрут её не переносить и старую блокировку не считать причиной отключения отправки. Проверка нового адреса успешна; повторной настройки Cloudflare для этого подключения сейчас не требуется.

## API для бронирования корта в UDC — безопасная повторная проверка доступа

```bash
python3 udc_check_access.py
```

Программа запросит ключ скрыто, отправит только неверную дату и покажет статус/ошибку без ключа. Она не создаёт выдуманную игру. Нормальный результат — приведённая выше ошибка формата; 401 означает отказ ключа и прекращение попыток.

## API для бронирования корта в UDC — реальные проверки после подключения

1. Прочитать подтверждение собственной игры в истории UDC: дата, корт, часы, `Active / Confirmed` у каждого часа.
2. Проверить `--preview-sync`, затем передать те же фактические данные через `--sync-confirmed` или addTennisBooking. Соседние часы одного корта передаются одной записью.
3. Различать `calendar=true`, `calendar=false` и `duplicate=true`; только первый ответ означает подтверждённое добавление в календарь.
4. При сетевой ошибке или HTTP 5xx повторять то же тело до трёх раз с паузой 60 секунд; после исчерпания сообщить владельцу. Это максимум четыре запроса с первоначальным. При 401 повторов нет.
5. Фактические правила недели, добавление в календарь/Джарвис и уведомление выполняет сервер по предоставленному контракту. Клиент с ключом добавления не получает прав чтения или изменения внутренних данных сервера.
